# --- local tool backings -------------------------------------------------
# Each is imported lazily, inside the tool that needs it, so a missing package
# only affects that one tool: it still gets declared to Claude and returns an
# install hint if used. Drop any tool you don't want by removing its module

# 8.9.1 is a soft floor, not a hard one: it is where KernelManager grew
# `transport_encryption` (8.9.0 shipped it but broke restart, which core/kernel.py
# uses), so it is what buys CurveZMQ-encrypted sockets instead of plaintext on
# four loopback ports. Below it the tool still runs, but in the clear.
#
# Treat it as close to a hard floor. ZeroMQ's ipc:// transport has no Windows
# implementation, so there is no unencrypted-but-not-a-listening-port middle
# ground (see core/kernel.py): CurveZMQ is the only thing between the kernel
# link and plaintext TCP.

# `speak`/`listen` — fully local voice I/O, no cloud STT/TTS. Ported from the
# Linux client's parecord/paplay/`python3 -m piper` subprocess calls to
# in-process calls against these packages instead — see core/speak.py and
# core/listen.py module docstrings for the full reasoning. Both tools are
# declared either way and return a {"status": "not_configured", ...} result
# until [speak]/[listen] in config.toml are set up (listen actually needs no
# config at all if a default microphone exists — see its docstring).
piper-tts>=1.8           # `speak` — local neural TTS (core/speak.py), used via the
                         # `piper.PiperVoice` Python API, not the `piper` CLI binary.
                         # NOT `sudo apt install piper`/similar — unrelated project,
                         # same name, only applies to Linux anyway.
faster-whisper>=1.0      # `listen` — local CPU speech-to-text (core/listen.py), via
                         # `faster_whisper.WhisperModel` directly — no CLI entry point.
sounddevice>=0.5         # `speak`/`listen` — audio playback and microphone capture on

mido[ports-rtmidi]>=1.3  # `midi1` — MIDI 1.0 device I/O (core/midi1.py), ported
                         # byte-identical from the Linux client — the only OS-specific
                         # code is one illustrative comment, since `mido`/`python-rtmidi`
                         # already speak the same API over WinMM/WinRT here as they do
                         # over ALSA/JACK on Linux or CoreMIDI on macOS. The
                         # `[ports-rtmidi]` extra pulls in `python-rtmidi`, mido's actual

                         # install hint" contract as every other tool in this section.

# --- system binaries, not pip ------------------------------------------------
# `document_convert` shells out to these:
#   winget install TheDocumentFoundation.LibreOffice  # docx/odt/xlsx/pptx <-> pdf
#   winget install JohnMacFarlane.Pandoc              # markdown -> docx/odt/pdf
#
# LibreOffice does not add itself to PATH, so core/documents.py also looks in
# C:\Program Files\LibreOffice\program. It invokes soffice.com, not soffice.exe:
# the .exe detaches and returns 0 before converting anything. Pandoc's installer
# does extend PATH, but an already-running shell keeps the old copy — restart
# this client after installing it.
#
# `computer` needs no system packages: pyautogui and pillow above are the whole
# dependency, and screen capture works out of the box.
